# API

Серверная часть отвечает за аккаунты и сессии, права на функции, подписки и платёжные уведомления, лимиты AI и аналитику. Авторизация и проверка прав выполняются на сервере.

## Supabase Auth

Для разработки установите Supabase CLI и запустите Docker. Из корня репозитория:

```sh
cd apps/api
supabase start
supabase status
```

Supabase Auth обслуживает подтверждение email, пользователей и сессии. Шаблоны
подтверждения и повторного входа отправляют шестизначный код, срок действия
которого установлен в `supabase/config.toml`. Локальные письма попадают в Mailpit.
Веб-сервер обращается к Auth через `auth.mjs` и хранит сессию в HttpOnly cookies.

Для внутреннего развёртывания на Mac mini можно запустить веб-сервер рядом с
Docker-стеком. Укажите LAN-имя в `APP_ORIGIN` и используйте HTTPS через reverse
proxy. При проксировании на той же машине оставьте `HOST=127.0.0.1`; веб-сервер
будет ставить Secure cookies при HTTPS. Доступ браузера нужен только к сайту.
Для отправки писем в реальные почтовые ящики потребуется SMTP и настройка
обоих шаблонов Auth в выбранной конфигурации Supabase.

На Mac mini ограничьте доступ к служебным портам Supabase, включая API,
Postgres, Studio и Mailpit, локальной машиной. В LAN публикуйте HTTPS-вход
веб-приложения. При нескольких пользователях учитывайте, что серверные запросы
к Auth используют общий IP и разделяют его лимит.
